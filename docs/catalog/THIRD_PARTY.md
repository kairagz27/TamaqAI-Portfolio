# Локальное чтение штрихкода

Используется **ZXing Core 3.5.4**: `com.google.zxing:core:3.5.4`.

- [Официальный выпуск 3.5.4](https://github.com/zxing/zxing/releases/tag/zxing-3.5.4).
- [Исходники Core этой версии](https://github.com/zxing/zxing/tree/zxing-3.5.4/core).
- [LICENSE в зафиксированной версии](https://github.com/zxing/zxing/blob/zxing-3.5.4/LICENSE), Apache License 2.0 и перечисленные в нём уведомления.
- [NOTICE в зафиксированной версии](https://github.com/zxing/zxing/blob/zxing-3.5.4/NOTICE).

Подключён только декодер Core. Существующий CameraX делает снимок, приложение ограничивает размер bitmap и декодирует GTIN локально. Отдельный scanner Activity, Google ML Kit, Firebase и загрузка изображения в Google не используются. Название пакета `com.google.zxing` само по себе не означает облачную обработку. После декодирования backend получает только запрос поиска по коду; анализ AI для этого не вызывается.

EAN-13, EAN-8, UPC-A и UPC-E читаются как идентификаторы товара. При отсутствии распознавания или записи каталога пользователь должен перейти к поиску по названию/ручному вводу. Внешний вид упаковки не назначает бренд. Фотография камеры временная, удаляется после декодирования; её не включают в seed или Git.

Полные тексты официального тега сохранены в `app/src/main/assets/third-party-licenses/zxing-LICENSE.txt` и `zxing-NOTICE.txt`. В LICENSE репозитория также есть уведомление jai-imageio; это сохранение исходного файла, а не подключение jai-imageio в Android. Наличие файлов в итоговом APK проверяется вместе с упаковкой приложения. Изменение версии зависимости требует повторной проверки лицензии и локального декодирования; платные AI-вызовы для такой проверки не нужны.
