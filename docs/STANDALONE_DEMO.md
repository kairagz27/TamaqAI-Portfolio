# Автономное Android-демо

`standaloneDemo` — отдельная локальная версия TamaqAI для портфолио. После установки
она не требует Docker, backend, регистрации, email, компьютера, интернета или
`adb reverse`. Установка APK вручную может потребовать разрешения Android для
выбранного источника. Обычный серверный вариант `demo` сохранён отдельно:
[его запуск](DEMO.md) по-прежнему требует backend на порту 8100.

**Это демонстрационная версия. AI-анализ демонстрационный.** Все записи и профиль
хранятся на устройстве. Это не распознавание произвольной фотографии, не внешняя
регистрация и не облачная резервная копия дневника.

## Два независимых варианта

| Вариант | Пакет | Источник данных | Сеть |
|---|---|---|---|
| Автономный `standaloneDemo` | `com.tamaqai.standalone` | Локальные реализации репозиториев, Room, встроенные примеры | Разрешение `INTERNET` удалено из manifest |
| Технический `demo` | `com.tamaqai.demo` | Локальный FastAPI/PostgreSQL и явно поддельный provider | Backend 8100 и `adb reverse` |
| Рабочие `debug` / `release` | `com.tamaqai` | Существующая конфигурация backend | Исходные правила доступа сохранены |

Версия нового пакета: `1.4.0-standalone.1`, versionCode `6`. Его данные изолированы
песочницей Android. Не удаляйте рабочий TamaqAI и не очищайте его данные ради демо.
Для обновления автономного пакета поверх установленного нужна та же подпись APK.
Ключ подписи не хранится в репозитории.

## Что попробовать

1. Откройте приложение и нажмите «Попробовать» на коротком приветствии.
2. Откройте встроенный пример через действие добавления еды. Фотография и
   подготовленный ответ относятся к одному выбранному примеру; произвольное фото
   не получает подставной результат.
3. В настоящем редакторе измените массу отдельного компонента, затем съеденную
   долю. Пересчёт использует исходную оценку, без обращения к модели.
4. Подтвердите приём пищи и проверьте дневные итоги, историю и запись после
   перезапуска. Черновик сам по себе не означает, что еда съедена.
5. Найдите продукт во встроенном каталоге, выберите количество и подтвердите
   запись. Проверьте сохранённый снимок состава в дневнике.
6. Откройте план питания, измените его локально. Приём из плана попадает в дневник
   только по явному действию пользователя; повторное подтверждение того же приёма
   использует стабильный идентификатор.
7. Измените локальный профиль, цели, язык или тему. Учётной записи на сервере при
   этом не создаётся.

Произвольную еду можно добавить вручную. Камера/галерея не предоставляют автономное
AI-распознавание. Инфраструктурные операции не должны молча обращаться к серверу:
приложение объясняет их недоступность в автономном варианте.

## Данные и сброс

Первый запуск создаёт синтетический профиль без контактов, цели, шесть приёмов за
три дня, четыре измерения веса и редактируемый план. Даты привязаны к `Clock`,
переданному через composition root. Начальная дата сохраняется до импорта, поэтому
повтор после прерывания использует те же идентификаторы и даты. Завершённая
инициализация не повторяется при следующем запуске или на следующий день.
Ручные изменения не заменяются исходным набором.

Явный сброс демонстрации требует подтверждения, очищает только данные владельца
`standalone` внутри отдельного пакета и восстанавливает набор. Выбор темы и языка
сохраняется. Маркер незавершённого сброса позволяет повторить очистку/инициализацию
после прерывания. Этот механизм не касается серверных лимитов, ledger или Room
других пакетов.

## Сборка из исходников

Разработчику нужны JDK 21 и Android SDK 36. Они нужны для сборки, не для использования
уже установленного APK. Секреты и backend URL не требуются:

```sh
./gradlew assembleStandaloneDemo
```

Результат: `app/build/outputs/apk/standaloneDemo/app-standaloneDemo.apk`.
На Windows используйте `./gradlew.bat`. Для установки разработчиком на выбранное
устройство, без reverse tunnel:

```sh
adb -s DEVICE_ID install -r app/build/outputs/apk/standaloneDemo/app-standaloneDemo.apk
```

## Проверки

Следующие команды — воспроизводимая инструкция. Их наличие здесь само по себе
не означает, что проверка выполнена; результаты фиксируются отдельно ниже.

```sh
python tools/test_standalone_tools.py
python tools/check_standalone.py
./gradlew assembleStandaloneDemo testStandaloneDemoUnitTest lintStandaloneDemo -PtamaqStandaloneTest=true
./gradlew connectedStandaloneDemoAndroidTest -PtamaqStandaloneTest=true -Pandroid.testInstrumentationRunnerArguments.class=com.tamaqai.data.StandaloneDemoPersistenceTest
```

`tamaqStandaloneTest=true` выбирает тестовый build type. Без него Gradle оставляет
обычный `debug` и может не создать задачи `testStandaloneDemoUnitTest` /
`connectedStandaloneDemoAndroidTest`. В CI отдельный job не поднимает backend или
PostgreSQL. Изолированный эмулятор работает в авиарежиме, Wi-Fi и mobile data
выключены, reverse tunnel отсутствует. Системные настройки реального телефона
не следует менять без согласования с владельцем.

Manifest проверяется не только по исходнику, но и по APK:

```sh
apkanalyzer manifest print app/build/outputs/apk/standaloneDemo/app-standaloneDemo.apk > standalone-manifest.xml
python tools/check_standalone.py --manifest standalone-manifest.xml
```

Дополнительно собираются прежние варианты:

```sh
./gradlew assembleDebug assembleRelease assembleDemo testDebugUnitTest lintDebug lintRelease lintDemo -PtamaqEnvironment=usb -PtamaqReleaseBackendUrl=https://pilot.example.com
```

Здесь `pilot.example.com` — безопасный пример адреса только для проверки конфигурации
сборки, не работающее размещение пилота. Backend и платные модели этими командами
не вызываются.

  Запись экрана использует только синтетические локальные записи.

Исправленные при проверке проблемы: переход в редактор после Room явно выполняется
на Main dispatcher; повтор открытия использует уже созданный черновик; встроенный
каталог отличается от режима «только кеш»; прозрачная панель наследует контраст
системных иконок родительского окна. UI-тест отдельно ожидает редактор и опубликованный
дневной итог, учитывает объединённые семантики карточки и вертикальный список.

При повторном объединённом прогоне 8 Android-проверок один UI-тест на сбросе
попал в известный Espresso/Compose idle timeout и ошибку `LifecycleRegistry.removeObserver`
в тестовом `TestMonotonicFrameClock` вне Main thread; остальные 7 прошли. Этот
неудачный прогон не засчитан как успех. Повторный выборочный UI-прогон профиля/плана/каталога/ручной еды/сброса прошёл
за 23 секунды. Обычные adb-касания вне Compose runner также подтвердили reset → приветствие →
повторный вход → холодный запуск, с сохранением **kk / Dark**; финальная база
содержит **6 записей и 4 веса до/после**, строки совпадают. Причина нестабильности всего тестового окружения не объявлена
устранённой.

**Ограничения:** физический телефон не подключён; плавность Xiaomi/других устройств
не подтверждена. Полный legacy Espresso-набор не заявлен пройденным. GitHub CI
запускается для коммита ветки: [актуальные результаты](https://github.com/kairagz27/TamaqAI-Portfolio/actions/workflows/verify.yml).
Платные AI-вызовы: **0**, расход **$0**. Старый релиз не изменён.

Известная нестабильность широких Espresso/Compose UI-проверок (idle/SlotWriter при
переходах и завершении Activity) остаётся описанной в
[публикационной проверке](PUBLICATION_VERIFICATION.md). Успешный выборочный тест
хранения не означает устранения этой причины или прохождения всего UI-набора.
